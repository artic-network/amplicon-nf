# artic-network/amplicon-nf: Pathoplexus submissions

By default amplicon-nf prepares one upload folder per primer scheme for [Pathoplexus](https://pathoplexus.org). Each folder holds a metadata template, a FASTA file and the dehosted reads. As much of the metadata as possible is filled in from the run, so you only need to add the sample-level information the pipeline cannot know.

> [!CAUTION]
> **This is designed for single-target tiled amplicon schemes: one organism per primer scheme.**
>
> - **Segmented genomes** (e.g. CCHFV, Andes virus) are supported: a sample's segments become one Pathoplexus entry.
> - **Reference-selecting schemes** (e.g. `artic-pan-ebola`, where artic picks the closest variant reference for each sample) are supported: the primers are the same for every sample, and each sample has one consensus sequence.
>
> It is **NOT** designed for primer panels or multi-pathogen schemes, where the reference contains several sequences that are not segments of one genome. Any sample with more than one consensus record is treated as **one segmented genome**, which is wrong for these schemes. Do not upload the generated files for panel data.

To turn it off, set `--skip_pathoplexus_template`.

## Output folder

```
<outdir>/pathoplexus/<SCHEME>/                 # e.g. artic-pan-ebola_1000_v2.0.0 ("/" replaced with "_")
├── <SCHEME>_pathoplexus_metadata.xlsx         # metadata template (website upload)
├── <SCHEME>_pathoplexus_metadata.tsv          # same rows and columns (website or API upload)
├── <SCHEME>_pathoplexus_sequences.fasta       # consensus sequences, IDs matching the metadata
└── raw_reads/                                 # dehosted reads, headers stripped (not written with --skip_dehosting)
    ├── <SAMPLE>.dehosted.fastq.gz             # Nanopore
    ├── <SAMPLE>_R1.dehosted.fastq.gz          # Illumina
    └── <SAMPLE>_R2.dehosted.fastq.gz
```

The XLSX has the same layout as the template you can download from the Pathoplexus website:

| Sheet      | Contents                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Data`     | One row per sample. Machine field names as column headers. Header colours show the Pathoplexus requirement level. **Orange headers are the columns for you to fill in**, and their empty cells are shaded (red: required, yellow: recommended). Auto-filled values are in grey italics. Hovering over a header shows the field's definition and guidance. Dropdowns are provided for controlled-vocabulary fields (country, instrument, assay type). |
| `_lists`   | Hidden, protected sheet holding the dropdown values.                                                                                                                                                                                                                                                                                                                                                                                                 |
| `Guidance` | Protected sheet listing the fields to fill in, upload instructions, any samples left out of the template, any values to check, a colour key, a table of every field, and provenance (pipeline version and the Pathoplexus specification version used).                                                                                                                                                                                               |

Pathoplexus reads only the `Data` sheet. Do not add extra sheets, as they cause a warning on upload.

## What you need to fill in

| Field                  | Pathoplexus requirement                                              | Notes                                                                                                                                                             |
| ---------------------- | -------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `sampleCollectionDate` | Required                                                             | `YYYY-MM-DD`, `YYYY-MM` or `YYYY`. The column is formatted as text, so Excel will not convert dates.                                                              |
| `geoLocCountry`        | Required                                                             | Choose from the dropdown (INSDC country list).                                                                                                                    |
| `authors`              | Required                                                             | `Last name, First name; ...` separated by semicolons, e.g. `Smith, Anna; Perez, Tom J.; Xu,;`.                                                                    |
| `host`                 | Desired; **required for dengue, yellow fever, zika and chikungunya** | Scientific name (e.g. `Homo sapiens`) or NCBI taxon ID. Use `unidentified` if unknown. For those four organisms, Pathoplexus processing fails if `host` is empty. |
| `geoLocAdmin1`         | Desired                                                              | First sub-national level, e.g. province or state.                                                                                                                 |
| `geoLocAdmin2`         | Desired                                                              | Second sub-national level, e.g. district or city.                                                                                                                 |

None of these can be inferred safely from the sequencing data, so they are always left blank. You can add any other Pathoplexus metadata field as an extra column, using its exact field name (e.g. `specimenCollectorSampleId`, `purposeOfSequencing`). Pathoplexus ignores empty cells.

## Pre-filled fields

Notation used below:

- `<pipeline>` is the pipeline name and version, e.g. `artic-network/amplicon-nf v0.12.0-g44f4001`. The version includes the exact commit (`-g<commit>`), with `-dirty` appended when the pipeline code had uncommitted changes, or `-commit-unknown` when the commit could not be determined. No individual tool versions are recorded.
- "Kept records" means a sample's consensus records that have at least one called base (entirely-`N` records are dropped, see [Which samples are included](#which-samples-are-included)).
- "Length-weighted" means averaged over the kept records, weighted by record length (for single-record samples this is just the value).

### Nanopore flow cell types

The flow cell type comes from the `flow_cell_id` in the read headers. Only the Flongle ID format is documented by Oxford Nanopore. The `F…` and `P…` prefixes are a widely observed convention.

| Flow cell ID pattern            | Example    | Flow cell type | `sequencingInstrument`                                      |
| ------------------------------- | ---------- | -------------- | ----------------------------------------------------------- |
| three letters, three digits     | `ABC123`   | Flongle        | `OXFORD_NANOPORE`                                           |
| `F` + two letters + five digits | `FBH86191` | MinION         | `OXFORD_NANOPORE` (MinION and GridION cannot be told apart) |
| `P` + two letters + five digits | `PAM69124` | PromethION     | `PromethION`                                                |
| anything else                   |            | not stated     | `OXFORD_NANOPORE`                                           |

If a sample's reads come from several runs, `sequencingProtocol` lists each run with its own flow cell ID and type. `sequencingInstrument` is only `PromethION` if every run used a PromethION flow cell, otherwise it is `OXFORD_NANOPORE`.

### Illumina instrument models

The instrument ID is the first `:`-separated field of the read names (e.g. `@VL00797:3:AAFH72VM5:...`). The first 1,000 R1 read names are checked. The prefix table is the community-maintained one ([fastp PR #508](https://github.com/OpenGene/fastp/pull/508)), with Illumina's own table used to split NextSeq 500 from 550. Prefixes it leaves ambiguous stay at the platform level.

| Prefix                                                                                                                                | `sequencingInstrument`  |
| ------------------------------------------------------------------------------------------------------------------------------------- | ----------------------- |
| `MN`                                                                                                                                  | `Illumina MiniSeq`      |
| `M` + digit                                                                                                                           | `Illumina MiSeq`        |
| `FS`                                                                                                                                  | `Illumina iSeq 100`     |
| `NS50`, `NB50`, `NL50`                                                                                                                | `NextSeq 500`           |
| `NS55`, `NB55`                                                                                                                        | `NextSeq 550`           |
| `A` + digit, `NA`                                                                                                                     | `Illumina NovaSeq 6000` |
| `LL`                                                                                                                                  | `Illumina NovaSeq X`    |
| `VH`, `VL` (NextSeq 1000 or 2000), `LH` (NovaSeq X or X Plus), `SH` (MiSeq i100), anything else, or several instruments in one sample | `ILLUMINA`              |

## Which samples are included

| Situation                                                     | What happens                                                                                                                                                                                      |
| ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Sample failed QC (`fail` / `warning`)                         | **Included**, with the QC fields filled in. Remove it yourself if you do not want to submit it (see [Before uploading](#before-uploading)).                                                       |
| Sample produced no consensus (assembly failed)                | Not included (there is nothing to submit).                                                                                                                                                        |
| Consensus entirely `N`                                        | **Left out entirely** (no row, no sequence, no reads), with a warning in the pipeline log. It is also listed on the `Guidance` sheet. Pathoplexus accepts such sequences but cannot process them. |
| A segmented sample with some segments entirely `N`            | Those segments are dropped from the FASTA and `fastaIds`. The remaining segments are submitted.                                                                                                   |
| Read file name with characters other than `A-Z a-z 0-9 _ . -` | Reads not prepared for that sample (Pathoplexus rejects such names), with a warning.                                                                                                              |
| Read file larger than 2 GiB                                   | Kept, with a warning. Pathoplexus's upload limit is 2 GiB per file.                                                                                                                               |

## FASTA IDs

- **Unsegmented samples:** the sequence ID is the sample name (`>SAMPLE`), which links it to the metadata `id`.
- **Segmented samples:** each segment is named `>SAMPLE_<reference name>`, and the IDs are listed in `fastaIds`.
- **Check:** the pipeline checks that the FASTA IDs and the metadata match exactly before writing the files, because Pathoplexus rejects the whole upload otherwise.

`fastaIds` is only accepted by Pathoplexus for segmented organisms (currently Andes virus and CCHFV). Unsegmented schemes never get this column.

## Raw reads

- **Reads come from the dehosting step.** Pathoplexus requires host reads to be removed, so raw reads are only prepared when dehosting (Deacon) runs. With `--skip_dehosting`, the `raw_reads/` folder and the `files.rawReads` column are left out and a warning is printed.
- **Nanopore reads are unfiltered.** They are the dehosted reads **before** `artic guppyplex` length and quality filtering, i.e. all reads minus host reads.
- **FASTQ headers are stripped to the read ID.** Everything after the first space in each header is removed, and the `+` separator lines are reduced to `+`. Sequences and qualities are unchanged. For Nanopore this removes the run ID, flow cell ID, start time, barcode, basecaller details and the MinKNOW `sample_id` / `protocol_group_id`, which often carry local sample names or places. The metadata the template needs is read from the full headers first. Illumina read IDs keep their standard form (instrument, run number, flow cell, lane and tile), which is needed to keep pairs matched.
- **Folder contents:** `raw_reads/` contains exactly the files named in `files.rawReads`. This is required for the website's folder upload, which blocks the submission if there are unreferenced or missing files.
- **Disk space, time and transfer:** the header-stripped copies are new files (gzip level 3, a little larger than a default gzip), so the dehosted reads take up roughly twice the disk space in the work directory and once more in `raw_reads/`. Rewriting runs at roughly 10 MB of compressed input per second, e.g. about 2.5 minutes for a 1.5 GB Illumina pair. On cloud executors the reads are transferred into and out of a task.

## Before uploading

1. Fill in the orange columns on the `Data` sheet (or the corresponding TSV columns).
2. Check the auto-filled values.
3. To leave a sample out, delete:

   - its row in the metadata
   - its record(s) in `<SCHEME>_pathoplexus_sequences.fasta`
   - its file(s) in `raw_reads/`

   All three must stay in step.

## Uploading

- **Website:**
  - Upload the XLSX (or the TSV) as metadata and the FASTA as sequences.
  - For raw reads, choose **Upload folder** and select the `raw_reads/` folder.
- **API:**
  - Submit the TSV and the FASTA.
  - Raw reads must first be uploaded separately (`/files/request-upload`), and `files.rawReads` replaced with `fileName:fileId` pairs. See the [Pathoplexus documentation](https://pathoplexus.org/docs).

## Organism differences

The template uses the metadata fields that are shared by every Pathoplexus organism, so the same template works for all of them. The organism-specific differences that matter are:

- **`host`:** required for dengue, yellow fever, zika and chikungunya (see above).
- **`fastaIds`:** only accepted for segmented organisms (Andes virus, CCHFV).
- **Organism-only fields:** optional fields such as `gisaidIsolateId` exist for some organisms only. They are not in the template, but you can add them as extra columns.

## Template definition

The field names, definitions, guidance and dropdown values come from a local copy of the Pathoplexus submission specification: [`assets/pathoplexus_template.toml`](../assets/pathoplexus_template.toml).

- **Nothing is downloaded at runtime.**
- **What the file defines:** the columns and their order. Whether a field is auto-filled is decided by the pipeline. Every field in the file that the pipeline does not fill is highlighted for you to fill in.
- **Provenance:** the file records the Pathoplexus version it was copied from.
- **Updating:** its header describes how to update it when Pathoplexus changes its specification.
